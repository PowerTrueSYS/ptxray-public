What PTxray answers

Where does this AIX or IBM i system actually stand?

PTxray reads observable posture across lifecycle, patching, storage, performance, errors, resilience, security, configuration, and monitoring. It reports the evidence; it does not repair the host.

01 / BOUNDARY

Read-only

System configuration is inspected, never remediated. Requested report paths are the operator-controlled output.

02 / EGRESS

Assessment stays offline

Assessment execution does not fetch definitions, open network connections, send telemetry, or transmit report data.

03 / RUNTIME

Inspectable platform files

The AIX report bundle uses KornShell and native ksh93 for IBM FLRTVC; the IBM i bundle runs under PASE ksh. OpenSSL verifies signed inputs. Connected AIX acquisition also needs curl and unzip.

04 / HONESTY

No fabricated status

Unavailable or ambiguous evidence can be NOT_ASSESSED; it is not silently reported as a pass.

Published PTxray 1.8.1 release

Current signed release behavior.

PTxray 1.8.1 is the current published release at releases/latest. Its AIX runner requires root, and its IBM i runner requires QSECOFR. The VIOS lane remains disabled pending live acceptance. Before assessment probes begin, the runner verifies and invokes the separate, adjacent, same-package digest-verified ptxray-defs.sh.

Extract the signed bundle for your platform. Run ksh dist/tools/aixray-scan.ksh --html --pdf --json --compliance all --out report on AIX, or ksh dist/tools/ibmi-scan.ksh --html --json --compliance all --out report on IBM i. Create the output directory first. The top-level runner copies require the complete extracted bundle.

AIX automatically captures fileset and interim-fix inventory, runs the verified IBM FLRTVC engine offline, and includes completed exposure findings in the report. IBM i runs its full platform catalog and reports unavailable evidence explicitly. Neither a completed run nor a PASS proves benchmark compliance.

The separate downloader acquires signed definitions and, on AIX, the pinned IBM engine before assessment. Connected mode discloses its requests and protected cache writes; it sends no assessment data. --offline uses verified cached inputs. A transferred local signed bundle includes its adjacent signature; offline AIX also needs the pinned engine staged in advance.

Assessment probes make no network calls, send no telemetry or assessment data, change no system configuration, and perform no remediation. Old, missing, or invalid data remains visible in the report.
